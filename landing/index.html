Guide

Install it, point it at your machine, and extend it.

agentglass is a desktop app with its own server bundled inside. There is nothing to run in a terminal and no port to open in a browser.

Getting it running

Take the installer for your platformSix files on the release. Linux gets an AppImage or a .deb; macOS has a separate build for Apple silicon and Intel; Windows is an NSIS .exe. The desktop builds are attested — gh attestation verify <file> --repo SirAllap/agentglass names the commit and the workflow that produced yours.
Launch it. That is the installThe cockpit opens with the server inside it. On first open the transcript scanner has already read ~/.claude/projects, so every Claude Code session on the machine is listed with no wiring at all.
Wire the hooks, once, if you want liveThe scanner shows history; the hooks add live streaming and PreToolUse gating — the hold. Settings ▸ Hooks writes them into ~/.claude/settings.json and takes them out again, and says whether they are in right now.
Pair the phone, if you want the queue with youTurn on remote access on the computer, scan the code from the Android app, type the six digits, accept on the desktop. It pairs over your own wifi: no account, and nobody's server in between.

What it expects to find

It drives the tools you already have rather than bundling its own, so the list is about what each feature shells out to — and what quietly stands down when it is missing. Settings ▸ Requirements checks every one of these on your machine and says what breaks without each.

gitneededSource control, file changes, pull requests, worktrees, and deciding where the terminal opens.
Claude Code CLIneededThe chat panel runs claude. Without it sessions still appear — the scanner reads the transcripts either way — you just cannot chat from the app.
Python 3neededThe hook forwarder.
tmuxper featureChats as live panes, your tmux windows as tabs, theme sync.
GitHub CLIper featureThe pull-requests panel — and logged in, which is the step people miss.
Dockerper featureContainers, images, volumes, logs.

Plugins

A plugin is a program somebody else wrote that watches or drives agentglass over HTTP. It is a folder with a plugin.json, and installing it, reading what it asks for, and switching it on are three separate acts you perform in Settings ▸ Plugins.

Nothing runs at install. When you enable one, the server mints a token at the scope you granted and starts the entrypoint as its own process, with exactly four variables in its environment: PATH, HOME, AGENTGLASS_URL and AGENTGLASS_READ_TOKEN. Nothing is loaded into the server or the desktop window. Disabling it kills the process and revokes the token; tokens live in memory and are never written to disk.

A plugin can also draw: a panel in the Plugins view, a page in Settings, notes in a pull request and a button in its header. It sends what to show as data, and agentglass draws it with its own parts. Browse the plugins.

readAlmost every GET route, including /stream: live output, costs, diffs, pull requests, the board. Cannot write anything, and cannot read another plugin's settings or screen.
answerEverything read gets, plus replying to a session already running. It cannot release a gate.
fullEverything this machine can do: a terminal, git writes, Docker, merging pull requests, installing other plugins.

The manifest is a request, not a grant: you see the scope and decide whether to enable it at all. A plugin cannot get full by writing "full" and being believed.

Finding one

A catalogue is a plain JSON file at an https:// URL, fetched fresh every time you browse it. It is a list, not a registry — nothing in it is cached as trustworthy between reads, and a catalogue that is unreachable or malformed is shown as exactly that, never as an empty list.

{
  "name": "community-plugins",
  "owner": "someone",
  "plugins": [{
    "id": "someone.hello-stream",
    "source": { "kind": "git", "url": "https://example.com/someone/hello-stream.git" },
    "description": "Writes a line to its log when an agent finishes.",
    "categories": ["monitoring"]
  }]
}

Full detail in PLUGINS.md and EXTENDING.md.

Questions

The things people ask before installing.

Short answers. Every one of them is also somewhere in the repository, linked where it matters.

Does it replace Claude Code, or my agent?

No. It attaches to the tmux sessions and repositories already open on your machine. It does not launch your agents and it does not proxy them — close agentglass and every agent keeps running.

Does anything leave my machine?

No account, no cloud, no telemetry. Everything lives in a SQLite file on your own disk.

Two paths can leave and both are off by default: a webhook you configure yourself, and the Explain button, which sends the hunks you point at to a model. SECURITY.md lists every switch.

What do I actually need installed?

Needed: git, the Claude Code CLI, and Python 3.

Per feature: tmux for chats as live panes and your tmux windows as tabs; the GitHub CLI for the pull-requests panel, logged in; Docker for containers, images and logs.

Settings ▸ Requirements checks all of it and says what stands down without each one.

Which agents, and which providers?

Agents: Claude Code, Codex, Gemini CLI and OpenCode.

Providers, for pointing Claude Code at something else: Kimi, OpenAI, Gemini and Bedrock.

Why does macOS say the app is damaged?

It is not damaged — the build is not signed yet, and Gatekeeper says that about anything unsigned. Once:

xattr -dr com.apple.quarantine /Applications/agentglass.app

Signing and notarization are the first item on the roadmap.

Can a plugin approve a held gate for me?

No, and it is turned away by name rather than by scope. A plugin's token is minted by this server and sits in the environment of a child process of it, readable by anything else running as the same user — which is exactly the kind of caller the gate exists to hold.

Releasing a gate is reserved for a credential no process on the machine could have minted for itself: a paired phone's, or a person at the desktop.

Can a plugin add a panel to the window?

Yes, within a closed vocabulary. A plugin declares where it draws — a panel in the Plugins view, a page in Settings, notes inside a pull request, a button in a pull request's header — and sends what to show as data. agentglass draws it with its own parts: there is no HTML, no stylesheet, no image by URL and no script. A tone is a word the app maps onto the current theme.

What is still not there is a surface of its own: an iframe with its own capability grants, where a plugin could draw anything it liked. That is a real design problem and it is undesigned, so it is not shipped under cover of "plugins". A plugin that needs one opens its own window today — it is a separate process and can start a terminal UI or a web page, talking over the same HTTP.

Is Windows supported?

It builds and passes CI, and nobody has run it on real hardware yet — #231 is open for exactly that. macOS builds are unsigned for now. Linux is the best-travelled path.

Publish one

01 · WRITE

One file at the root of a public repository. It is the whole manifest: what it runs, the scope it asks for, and where it draws.

{
  "name": "hello-stream",
  "publisher": "you",
  "description": "Writes a line to its log when an agent finishes.",
  "entrypoint": "python3 -u main.py",
  "scope": "read",
  "minApp": "0.17.0",
  "contributes": {
    "panels": [{ "id": "log", "title": "Hello" }]
  }
}

Add a preview.png beside it — a wide screenshot of the thing working. It is what the card above draws, and without one your plugin is listed as a puzzle piece. A README and a licence are the other two the check looks for.

Where it may write: its own folder, and what you ask the app to keep for you through /plugin/self/settings. Not the person's configuration — naming ~/.claude, ~/.config/agentglass, a shell rc, crontab or systemctl --user is enough to be flagged, because that directory holds the machine token and every other plugin on disk.

02 · TRY IT

Install it on your own machine before you ask anybody to list it. Four commands, and the last one leaves nothing behind:

agentglass-plugin validate .
agentglass-plugin add /abs/path/to/plugin --approve
# look at it in Settings → Plugins
agentglass-plugin remove your-plugin

validate is the same check the listing runs, so it is the cheapest way to find out that a manifest is wrong. --approve prints the scope, the command and every surface it draws on before it switches anything on.

03 · PUSH

Any host git clone reaches. The URL is already the publication: pasting it into Settings → Plugins installs it, with no account, no registry and nobody's permission. Being listed below is only about being found.

04 · LIST IT

Open the List a plugin issue. A check clones what you named, runs validate and reads the source for a short list of patterns — it never runs your code. A maintainer then approves, and the entry is written from your manifest into landing/plugins.json by a pull request somebody merges. Listing is not auditing: a plugin here has a public repository, a manifest the app accepts, a README and a licence. That is what a machine can tell, and whoever installs it still approves what it asks for. The guide has the routes and the drawing vocabulary.

Install one

In agentglass, open Settings → Plugins. This page's catalogue is offered there by name — press Add, open it, and install from the card. Or paste a plugin's URL straight in; the catalogue is a convenience, not a gate.

Nothing runs at install: you read what it asks for and switch it on, and an update that changes what it asks for is asked about again. Verified means a maintainer read that plugin at the listed source — it does not vouch for later changes, which is why an update always asks.
